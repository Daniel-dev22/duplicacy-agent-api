# duplicacy-api — Claude Project Instructions

## Goal

A Go REST + WebSocket wrapper around the duplicacy CLI, deployed as a docker-compose container on every Docker host. Sits behind Traefik with per-host hostnames; called by the controller router which fans out fleet-wide.

Read `README.md` first for the architecture summary. Read the canonical design at `/home/user/.claude/plans/yes-i-like-it-fluttering-patterson.md` for full context.

## Conventions

- **Go 1.25 minimum.** New packages: latest stable. Existing packages: match versions used by the controller sibling services (find them in `/srv/containers/controller/<service>/go.mod`).
- **No fallback imports.** No backwards-compat shims.
- **DRY + separation of concerns** across all code.
- **Connection pools required for every inter-service HTTP call.** Use the process-global `controlCenterClient` from `network.go` for talking to controller. Never instantiate `http.Client{}` per request — see CLAUDE.md "Standard HTTP Client Patterns" for the canonical patterns.
- **Atomic disk writes** for any file we write inside `.duplicacy/` (preferences, filters, autogenerated overlays) — write to `<file>.tmp` then `os.Rename`.
- **State persistence rule** (from `~/.claude/CLAUDE.md`): if losing a piece of state on agent restart would re-fire a notification or replay events, persist it to disk in `CONFIG_DIR`. Specifically: `events.sqlite` (lifecycle events not yet pushed), `schedules.json` (local schedule cache), `filters.global` (org+site filter cache).

## Duplicacy CLI behavior worth remembering

- **No JSON output.** Backup/restore/check/prune emit human-readable stdout. Stream raw stdout to WebSocket clients verbatim; only the *summary line* needs structured extraction.
- **Lock-free across hosts** — multiple `duplicacy backup` invocations against the same storage from different repos/hosts are safe by design. We don't need cross-host coordination.
- **Credentials**: env var `DUPLICACY_<STORAGENAME>_<PASSWORDTYPE>` (uppercase) → `keys` map in preferences (plaintext) → OS keyring → prompt. Keyring is non-functional in our containers (no daemon). We use the **plaintext-in-preferences** route, mode 0600, owned by container user. Same model as the saspus container we're replacing.
- **Repo state** lives in `.duplicacy/preferences` (JSON `Preference` struct from CLI source `duplicacy_preference.go`). One file per repo root.

## Build

`./build.sh --registry <REGISTRY>` — emits the same JSON that controller/build.sh emits, so the ansible build playbook handles it identically.
